15 / Reliability

Error & Exception Handling

Understand failures, catch expected problems, and keep a program's response clear and controlled.

Beginner+28 min read

01 / Overview

Not every failure is the same

A syntax error prevents Python from understanding the program. A runtime error happens while valid-looking code is running. Exception handling lets you respond to expected runtime problems without hiding every bug.

Syntax error

Python cannot parse the code.

Runtime error

The code starts, then an operation fails.

02 / Recognize Errors

Read the failure before fixing it

number = int("hello")

This is valid syntax, but the text cannot become an integer, so Python raises a ValueError. The exception name tells you what kind of operation failed.

💡 Debugging habit

Read the last line of the error first, then locate the line that triggered it.

03 / try & except

Handle one expected problem

try:
    number = int("hello")
except ValueError:
    print("Please enter a whole number")
OutputPlease enter a whole number

Python attempts the code in try. If the named exception occurs, the matching except block runs.

04 / Specific Exceptions

Catch what you understand

Prefer a specific exception such as ValueError or ZeroDivisionError over a broad catch. Specific handlers make the recovery behavior honest.

try:
    result = 10 / 0
except ZeroDivisionError:
    print("The denominator cannot be zero")

05 / Full Flow

else and finally

try: attempt the operation
⬇
Exception?
↙ no     yes ↘
else: success work
except: recovery work
⬇
finally: always-run cleanup

else runs only when no exception occurs. finally runs whether the operation succeeds or fails.

06 / Useful Patterns

Keep recovery small and useful

try: convert textPut only the risky operation in the try block.
except ValueError:Tell the user what kind of input is accepted.
else: use the resultKeep success-only work separate from recovery.

Exception handling is for expected problems; it should not replace careful code or debugging.

07 / Common Mistakes

Do not hide every failure

Too broadtry:
    do_work()
except:
    pass
Clearertry:
    number = int(text)
except ValueError:
    print("Use digits")

An empty broad handler can make real bugs invisible. Name the problem you expect and give a useful response.

08 / Do & Don't

Recover without losing meaning

Do

Catch specific expected exceptions and explain the next safe action.

Don't

Use except: with pass as a default response.

09 / What You Learned

Errors can be handled deliberately

  • Syntax and runtime errors happen at different stages.
  • try holds risky work.
  • except handles a named problem.
  • else is for success; finally always runs.
  • Specific handlers are easier to understand and debug.
